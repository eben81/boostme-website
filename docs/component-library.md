# Component Library

This document will inventory approved, reusable components as they are built.
No components have been implemented yet.

## Component workflow

1. Confirm the component scope and approved design decisions.
2. Check this library and `components/` for an existing implementation.
3. Build semantic, accessible HTML with a shallow DOM.
4. Use reusable classes and tokens from `css/variables.css`.
5. Document variants, states, dependencies, and responsive behavior here.
6. Validate keyboard behavior, reduced motion, and HTML-to-Bricks suitability.

## Directory ownership

| Directory | Intended contents |
| --- | --- |
| `components/hero/` | Approved hero implementation assets and notes |
| `components/header/` | Approved site-header implementation assets and notes |
| `components/buttons/` | Reusable button patterns |
| `components/cards/` | Reusable card patterns |
| `components/sections/` | Reusable page-section patterns |
| `components/footer/` | Approved site-footer implementation assets and notes |

Component folders intentionally remain empty until their components are
explicitly requested and approved.
